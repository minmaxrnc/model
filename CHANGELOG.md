# Changelog

## 0.4.0

Backward compatible with 0.3.0: with default settings, models have the same
API, parameter names, seeded initial weights, outputs, recurrent states and
sequence of PyTorch operations as in 0.3.0, and 0.3.0 checkpoints load with
`strict=True`. See [Upgrading from 0.3.0](docs/upgrading.md).

### Added

- **MinMax neurons of any state dimension.** A MinMax neuron with state
  dimension d updates x_t ∈ R^d by `x_{t+1} = max(R_t ⊗ x_t, s_t)` in the
  (max,min) semiring; d = 1 is the scalar-state neuron of 0.3.0.
  `MinMaxRNCConfig.neurons` adds groups of such neurons to every layer, each
  a `NeuronGroup(d_state, num_neurons=1)` or an equivalent tuple/list.
  R_t is an unconstrained affine projection of the input (d² entries per
  neuron). `MinMaxRNCConfig.scalar_neurons = N` is shorthand
  for the group `NeuronGroup(1, N)`: N scalar-state neurons.
  - New module `MinMaxNeuronGroup` / `MinMaxNeuronGroupConfig`, the single
    implementation for all state dimensions. Each group runs as one batched
    parallel scan: element-wise for d = 1 (the 0.3.0 computation, op for op),
    matrix-based for d > 1. The choice is made at construction.
  - New operator/scan functions `minmax_operator.apply_matrix`,
    `minmax_operator.compose_matrix`,
    `minmax_scan.all_composition_prefixes_matrix`,
    `minmax_scan.all_states_matrix`.
- **Recurrence precision.** `MinMaxRNCConfig.recurrence_dtype`: `None` (default,
  0.3.0 behaviour), or `'fp32'`, `'bf16'`, `'fp16'` to pin the recurrence's
  precision regardless of any autocast. With a pinned dtype the recurrent
  state is carried in that dtype.
- **Model-level mixed precision.** `MinMaxRNCConfig.amp_dtype`: `None`
  (default, the caller controls autocast as before), `'bf16'` or `'fp16'` to
  run `forward()` under `torch.autocast` (for the LM wrapper including the
  embedding and LM head).
- `MinMaxRNCConfig.neuron_groups`, `.num_scalar_neurons`,
  `.num_neurons_per_layer` and `.state_size_per_layer` properties.
- `MinMaxNeuronConfig.recurrence_dtype`, `MinMaxNeuronConfig._state_size_in_layer`
  and `MinMaxNeuronConfig.to_group_config()` (appended fields; defaults
  reproduce 0.3.0).
- `MinMaxLayerConfig.neuron_groups` (appended field; default `()`) and
  `MinMaxLayer.neuron_group_list()`.
- Package exports: `NeuronGroup`, `MinMaxNeuron`, `MinMaxNeuronConfig`,
  `MinMaxNeuronGroup`, `MinMaxNeuronGroupConfig`, `RecurrenceDtype`, `AmpDtype`,
  `__version__`.
- Tests: `tests/test_backward_compat.py` checks 0.4.0 against reference values
  recorded with 0.3.0 — weights, outputs, states and the forward pass's aten
  operation sequence (`tests/fixtures/v0_3_0_reference.pt`, regenerated by
  `tests/fixtures/make_v0_3_0_reference.py`); `tests/test_neuron_groups.py`;
  `tests/test_precision.py`.
- Docs: README sections on neurons of any state dimension, mixed precision
  and upgrading. The model documentation is split into `docs/foundations.md`
  (mathematical foundations, with the MinMax recurrence for any state
  dimension), `docs/architecture.md` (including initialisation),
  `docs/configuration.md`, `docs/precision.md` (numerical precision) and
  `docs/upgrading.md` (upgrading from 0.3.0), with the index in
  `docs/README.md`; `docs/model.md` only points there.
- Separate PyPI description: `README.md` uses GitHub's LaTeX math, and
  `README.pypi.md`, generated by `scripts/build_pypi_readme.py`, is the PyPI
  description (`pyproject.toml` `readme`), with formulas converted to
  PyPI-renderable HTML and relative links made absolute;
  `tests/test_pypi_readme.py` keeps the two in sync.

### Changed

- `MinMaxNeuron` is now a subclass of `MinMaxNeuronGroup`: the group of
  `cfg.d_state` scalar-state neurons. Its parameters, initialisation and
  computation are unchanged.
- `MinMaxRNCConfig.d_state` is now the legacy name of `scalar_neurons`:
  `d_state=N` builds exactly the same model as `scalar_neurons=N` (setting
  both raises `ValueError`); `num_scalar_neurons` gives the count either way.
  It now defaults to `0`: configs that set it behave exactly as before;
  leaving it out without `scalar_neurons` or `neurons` now raises
  `ValueError` (0.3.0 raised `TypeError`). The presets still set it, so
  `preset.d_state` keeps its 0.3.0 value.
- `MinMaxLayerConfig.neuron` may be `None` (a layer with only `neuron_groups`).
- The per-layer recurrent state gains a `'neuron_groups'` entry only for
  models with `neurons` groups, and has no `'neuron'` entry without scalar
  neurons; models with only scalar neurons keep exactly the 0.3.0 structure.
- Invalid `recurrence_dtype` / `amp_dtype` values raise `ValueError`.
